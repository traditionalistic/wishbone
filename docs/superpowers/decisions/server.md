## Store (`internal/store`)
Tables: `screens(id text pk, title text, draft jsonb, created_at, updated_at)`, `revisions(screen_id, rev int, source jsonb, document jsonb, etag text, runtime_min text, meta jsonb /* ops, data decls */, published_at, pk(screen_id, rev))`, `idempotency(key text, op text, request_hash bytea, status text /* in_flight|done */, response jsonb, created_at, pk(key, op))`, `audit(id bigserial, actor text, action text, entity text, at timestamptz, details jsonb)`. Live revision = max(rev). Publish = compile draft → insert rev = max+1 in one transaction (+ audit). Rollback = publish the source of rev N as a new revision and set it as the draft. Screen id must match `^[a-z0-9][a-z0-9._-]{0,63}$` (400 ARGS_INVALID otherwise).

## Public API (`internal/api`, exactly contract/api.md)
- `GET /v1/screens/{id}`: runtime check (semver of `X-Wishbone-Runtime` ≥ runtimeMin, missing header → treat as "1.0.0"), params from `?params=` merged over document param defaults, data resolved (below), ETag `"<rev>-<sha256(document)[:16]>"`, If-None-Match → document null (data still resolved).
- Data resolution: sources in parallel, per-source timeout 500 ms, whole budget 1200 ms; args JSON with `{"$param": name}` substituted from params; a failed `required` source → 503 DATA_REQUIRED_FAILED; non-required → `{ok: false, error}`.
- `POST /v1/data`, `POST /v1/call` per api.md: op must be in the revision's meta ops (call) — else 403 OPERATION_NOT_BOUND; unknown op 400; write ops require idempotencyKey (400), same key + different args hash → 409 IDEMPOTENCY_MISMATCH, in_flight → 409 CALL_IN_FLIGHT, done → stored response replayed without calling the handler; handler failure deletes the reservation. **Validate args against the op's DSL args type at this trust boundary** (reuse dsl.ParseType + a small JSON-vs-type checker) → 400 ARGS_INVALID.
- `GET /v1/theme?brand=` with version = sha256(file)[:16] and If-None-Match → 304; unknown brand → korpu.
- `GET /assets/*` from `contract/assets/`.
- Handlers resolve absolute asset URLs from the request (`scheme://host` honoring `X-Forwarded-Proto`/`Host`), so the Android emulator (10.0.2.2) and the iOS simulator (localhost) both get reachable URLs.

## Preview (`internal/preview`, exactly api.md + spec §5.4)
Sessions in memory: code = 4 chars from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, fields screen/title/source/document/data/devices/admins/updatedAt; expire after 2 h without activity (sweeper). `POST /admin/api/preview/{code}/document` compiles the posted source (not stored), resolves its data sources (params = defaults), stores it on the session and broadcasts `{"type":"document",…}`; diags returned either way. New device → immediate last document. Device `log` messages → admins as `{"type":"log","device",…}`; device list changes → admins `{"type":"devices",…}`. Unknown code → 404 (the admin recreates the session on 404).

## Upstream, unpublish, op timeouts (2026-09-28)

**Unpublish.** Migration `002`: `screens.unpublished_at timestamptz NULL`. `Store.Live` excludes a screen with `unpublished_at` set (`ErrNotFound`); `Publish` (feature publish and rollback share the path) clears the flag in the same transaction; `Unpublish(ctx, id, actor)` sets `unpublished_at = coalesce(unpublished_at, clock_timestamp())` (idempotent — a repeat call doesn't move the timestamp) and writes an `audit` row. `publishedRev` is untouched by unpublish — it stays the latest revision — so a server restart's `Seed` (which only creates screens absent from the DB) never republishes a screen someone took down. `Server.Recompile` at startup skips a screen with `sc.Unpublished` alongside one with `sc.PublishedRev == nil` (one guard): without it, `Live()` returning `ErrNotFound` for every unpublished screen made `Recompile` abort the whole startup on the first one found. `GET /v1/screens/{id}` for an unpublished screen → 404 `SCREEN_NOT_FOUND`; `/v1/data` and `/v1/call` addressed by revision number keep working regardless (an already-open screen session survives).

**Op `timeoutMs`.** `dsl.Op.Timeout` parses the optional `timeoutMs` (ms) from `operations.json`; 0 = the server default (`sourceTimeout`, 500 ms). `Server.timeout(op)` returns the op's timeout when set, else the default; a screen's data-resolve budget is `max(1200ms, max over its decls of timeout(op) + 200ms)` instead of the old fixed 1200 ms; each source's context is capped at `s.timeout(d.Op)`. `POST /v1/call` is **not** bounded by the source timeout (`postCall` calls `s.invoke` directly with the request context, or `context.WithoutCancel` for writes) — only the GraphQL client's own 10 s cutoff applies there.

**GraphQL upstream (`internal/ops/gql.go`, `raffle.go`).** `WISHBONE_GRAPHQL_URL` is the NewBackend GraphQL endpoint (stage: `https://stage.korputeam.ru/graphql`); unset → `raffle.*` ops answer `UPSTREAM_FAILED`. `WISHBONE_GRAPHQL_LOGIN` = `<phone>:<code>` (replaces the originally-specced `WISHBONE_GRAPHQL_FALLBACK_TOKEN` wherever it was mentioned) — the server logs itself in via the `WishboneLogin` mutation, because stage access tokens live only ~15 minutes and can't be handed over as a static token. The resulting token is cached with the expiry parsed out of the JWT payload, refreshed under a mutex-guarded single-flight login (a malformed/exp-less token caches 5 minutes instead); an `UNAUTHENTICATED` response to a fallback-token request clears the cache so the next read logs in again. This fallback identity is used **only for reads that arrive without an `Authorization` header** (admin preview, playgrounds); a **write** without `Authorization` fails `UNAUTHENTICATED` before any upstream call; a request that does carry `Authorization` forwards it verbatim. Error mapping: `errors[].extensions.code == "UNAUTHENTICATED"` → `UNAUTHENTICATED`; any other GraphQL error, non-200 HTTP, or transport failure (including the client's own 10 s timeout) → `UPSTREAM_FAILED` (new retryable code in `errors.json`); a response carrying both `errors` and non-null `data` still decodes (partial success is not an error). **`Accept-Language` is NOT forwarded to the upstream** (Ruling 3) — the server's own raffle labels are ru-only, so forwarding it would only risk mixing languages in upstream task names for no benefit; this corrects spec 2026-09-28 §3.1's original "прокидывается тоже". Tokens and response bodies are never logged.

**`raffle.*` assembly (`internal/ops/raffle_build.go`).** The pure build functions (`buildOverview`, `buildPromo`, `buildDaily`, `buildTasks`, `buildPrizes`, `dedupeRules`, `displayName`, `shareText`, …) are a faithful port of Stratoapp's `Modules/Raffle/Domain/Sources/Models/RaffleOverviewAssembler.swift` and `Modules/CoreNetworking/Sources/RaffleResponseMappers.swift`: same rule-dedup key `(isPromo, taskType, name)` first-wins for `tasks`/`rules` (not for the promo task-count, which reads the raw rule list like Stratoapp does); same task-join precedence (items sum `tickets`/`count`, progress is a max, target is the first item's non-nil target else the rule's); same prize grouping (smallest `raffleId`)/sort (tickets desc, name asc)/coin dedup exception; same daily-state thresholds. A change to the Stratoapp assembler should be ported here too, and vice versa.

**Compiler rule — lists must be direct children of a vertical lazy scroll.** In a `scroll` whose `lazy` is set (not the literal `false`) and whose `axis` isn't the literal `"h"`, every `repeat` reachable below a direct child (stopping at the first repeat on each path; not entering a nested `stack`/axis-h `scroll`) is a compile diagnostic: a row card taller than the screen, placed as one non-repeat child ahead of a footer, livelocks SwiftUI's `LazyVStack` on iOS 26 and stalls Compose paging on Android (Task 14b). The rule runs after template expansion, so it also catches templates, and has no severity — it blocks compile, preview, publish, seed and the startup `Recompile` alike. **Startup hazard (Ruling 11):** a live published revision predating a newly added compile rule fails to recompile, and `Recompile` refuses to start the server at all rather than skip that one screen — deploying a server build with a tightened rule while an old-shaped screen is still live bricks the server on its next restart. Handled operationally, not by changing `Recompile`'s refuse-vs-skip semantics: republish the new-shaped screen source under the OLD server first (it still compiles under the old rule set), then deploy the new server build. A future rule tightening needs the same two-step order.

**CA bundle.** The server image is `FROM scratch`, so it has no system trust store and the GraphQL client can't complete TLS to the upstream. `deploy/push.sh` copies the build machine's `/etc/ssl/cert.pem` (macOS system bundle) into the build context as `ca-certificates.crt`; `deploy/Dockerfile` copies it into the image at `/etc/ssl/certs/ca-certificates.crt` (Go's default lookup path on Linux).
